# BUG-001: /api/token/refresh response includes refresh token (contract mismatch)

Date: 2026-01-23
Branch: main
Commit: 8f5d6d3ea2ac8f0e2445e36dfa5e6ad85803b424
Status: Resolved

## Summary
`POST /api/token/refresh/` returns both `access` and `refresh` tokens, but the Phase 0 API contract specifies the response should include only a new `access` token.

## Environment
- Local backend (Django + DRF SimpleJWT)
- Base URL: /api

## Steps to Reproduce
1. Create a user.
2. `POST /api/token/` with valid credentials; capture the refresh token.
3. `POST /api/token/refresh/` with that refresh token.

## Expected
Response body matches API contract:
```
{ "access": "jwt" }
```

## Actual
Response includes a new refresh token as well:
```
{ "access": "...", "refresh": "..." }
```

## Impact
- Violates the Phase 0 API contract.
- Frontend does not persist rotated refresh tokens, which can cause refresh failures if token blacklisting is enabled.

## Notes
Backend settings enable refresh rotation (`ROTATE_REFRESH_TOKENS = True` and `BLACKLIST_AFTER_ROTATION = True`), so the refresh endpoint returns a new refresh token.
